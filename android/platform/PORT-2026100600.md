## Patch-stack port

All 41 ordered `frameworks/base` patches frozen by
`android/tools/stage_contract.py` and applied by
`android/platform/stage-os.py` apply without fuzz or manual conflict to the
new framework commit and produce 60 owned target files. The seven obsolete
API2 Shell reconnect/disconnect bookkeeping patches are not part of this
port; API3's WMS-owned physical-removal and fail-black paths own that lifecycle.
Launcher3's pinned
commit did not change, and its five ordered patches remain on the identical
baseline. The same schema-4 stage applies and hashes the two ordered Goldfish
patches, `emulator-freeform.patch` and `emulator-meta-keys.patch`; the former
selects the reviewed freeform capability and the latter makes the emulator's
Meta keys reachable from a hardware keyboard. The x86 configuration can no
longer be changed by an unreceipted post-stage helper.

The historical custom7 snapshot contained 40 framework patches / 53 targets
and four Launcher patches. The working-tree successor appends the reviewed
authoritative-focus framework and Launcher patches, adding six Kotlin files
and the private WM Shell query plus guarded Launcher hooks. Root reconstructed
the complete sequences against the exact pinned Git objects and passed the
integrated compiled host checks (1,158 actor/worker assertions and 24
stock/guarded method comparisons). The source7 checkout and its stage marker
remain unchanged. This update is patch-application/control-flow evidence;
Android compilation, fresh staged sibling, genuine Recents runtime and final
privileged review remain required. Pending keyboard-containment changes are
not included in these counts.

Between the historical `2026092500` framework commit and this baseline, the
only upstream change under the broad directories containing Wonad hooks is
`services/core/java/com/android/server/policy/keyguard/UsbPortSecurityHooks.java`.
It adds completion reporting to the platform USB data-signal operation. No
Wonad patch touches that file or its call path. Because external-display use
can involve USB-C, source non-overlap does not waive dock/hotplug testing on the
exact image and physical Pixel 10.

## Release-specific controls

- `frankel-cur-user` is the only production lunch target in the lock.
- `sdk_phone64_x86_64-cur-userdebug` is a development sibling from the same
  signed manifest and the same complete source freeze; it is not the ARM64
  binary image. Production receipts explicitly select `production` and claim
  no emulator artifact bytes.
- The source freeze authenticates the complete signed-manifest project ledger,
  default manifest bytes, repo tool, generated vendor tree, Goldfish targets,
  Android toolchain/prebuilts and locked builder image/configuration.
- A production release bundles the frozen SDK, signed conformance APK, public
  signer, compile receipt and source freeze. Development-qualified emulator
  records cannot be substituted.
- Production builds require an initially empty `out/` tree.
- Updater inclusion requires a project-owned HTTPS endpoint. The configurator
  rejects the official GrapheneOS domain and records the exact owned edit.
- The Wonad client certificate digest is supplied explicitly and baked into
  the broker stage. Debug/test signing is not accepted for a release, and the
  release preflight rejects reuse of any GrapheneOS OS-signing identity
  (including `platform`) as the Wonad identity.
- GrapheneOS/AVB/OTA private keys stay outside both this repository and the OS
  checkout. The signing wrapper temporarily links the selected key directory,
  refuses an existing output directory and refuses active swap by default.
- Incremental generation is locked to GrapheneOS `script/generate-delta.sh`
  from script-project commit `09d651841b55e42b9cee7392f0ce29ebda8c8fb5`
  (SHA-256
  `2e0f80721588ff8f45b298f8242e8af658297c1916ff276b9456c1b4e957ef63`).
  The driver requires an exact monotonic ten-digit predecessor/successor pair,
  refuses overwrite and binds both full-release receipts and the delta into a
  separately authenticated pair receipt.

## Still required for Phase 1 acceptance

Clean compile, emulator execution, fault injection, upstream/custom comparison,
soak, signed ARM64 artifact generation and offline receipt validation remain
runtime gates. Clean patch application is only porting evidence.
