# Separate vendor-memory proposal (not authorized for execution)

The retained G8 Docker observation says OOMKilled=true, exited, Pid0 and exit1 under a 40 GiB cap and equal swap limit. It does not contain a measured graph RSS/heap peak, prove that 48 GiB will fit, or authorize cleanup/retry.

Propose a fixed 48 GiB memory cap, equal 48 GiB memory-swap limit (no extra container swap), independent host admission of at least 48 GiB MemTotal and 42 GiB MemAvailable. This is the same memory envelope already configured for the separate ARM build launcher, not measured successful vendor generation. A 42 GiB available floor is below the cap: this is deliberately only a non-reserving launch snapshot, not a guarantee against later host/cgroup memory pressure. Host processes may still use host swap. Every observation and fresh command must be reviewed again immediately before any separately authorized retry.

The prospective patch is relative to the separately frozen terminal/outcome candidate. It changes only MEMORY, introduces MIN_MEM_AVAILABLE, and strengthens the memory observations in resources(). CPU affinity stays 0–3, quota4, PID2048, read-only root, three exact mounts, no KVM, no extra swap and all 14 pinned adevtool dependency targets unchanged. Storage >=64 GiB, FICLONE same-filesystem, online/allowed CPU and live-lane/debug exclusion guards remain unchanged. The old G8 40 GiB container does not match this new fixed profile; historical cleanup needs its own exact original-profile/custody authorization, not a profile waiver.

The original pinned build path clears the final graph builder's process environment with env -i; exporting GOMEMLIMIT/GOGC in the host/container does not cap that builder. The inspected stock code permits smaller affinity (runtime.NumCPU controls Go workers/visitors and default Siso jobs) and partial analysis, but neither is selected for this initial retry. Partial analysis still parses the graph/early mutators and has not been qualified here. No target omission, upstream edits, Ninja overrides or environment interception are proposed. SOONG_PROFILE_MEM is an observation option, not a heap cap; an OOM may prevent its output. The initial proposed retry keeps all14 targets and CPU0–3/quota4.

Files are prospective source/host-fixture evidence only. The renderer prints bytes or a patch and never writes/launches; tests compile those bytes under the original repository __file__ solely to model constants/control flow. No actual admission, Docker/container/caches/build/signing/VM is performed. Root must separately approve integration, updated source bindings, fresh recipe/profile and measured resource GO.
