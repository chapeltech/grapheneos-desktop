# Bounded ordered-handler protocol review

Read-only design review of preserved snapshot10 (receipt47fd68fc..., SHA256SUMS3f3c2e28...) and the producer's mutable successor proposal. No final mutable source hashes, implementation approval, platform compile or runtime proof is claimed here. Producer/peer/root received the schedules before successor freeze.

The confirmed inversion requires removing every stock KGC/Binder/UI callback from the helper monitor, including displaced-owner cancellation and delayed Escape. One-way remote delivery does not make a local InputManagerGlobal/PWM handler asynchronous. Synchronous work under the helper may publish/restore only exact local mirror references/booleans and safely enqueue an identity-bound ticket. The current source claim resolver also reads framework state; this bounded review does not relabel it as entirely lock-free or a whole-platform lock proof.

Minimal ordering: pure preparation creates exact pair/claim/focus/owner plus PENDING ticket; a known Handler enqueue succeeds before that state is externally accepted; the sole KGC Handler rechecks exact current/usable owner under helper and changes PENDING to ADMITTED; then releases helper before stock effects. Successful effect becomes STARTED even if lifecycle removed that exact owner after admission. Failure removes only that owner and records partial-effect cancellation outside helper. Lifecycle/UP requests carry exact ticket cleanup to the same Handler. A removed-before-commit owner cannot START; an admitted-before-retire owner must still receive ordered cancellation. Late old completion/CANCEL cannot mutate a replacement.

Three source-backed failure schedules must remain in focused extraction tests:

1. A frozen Handler with repeated DOWN/UP cycles empties active/drains each cycle but queues START+cleanup indefinitely. maximumPairs alone is not a queue bound. Keep an independent outstanding-ticket/cleanup budget until execution/definitive cancellation, or one bounded identity ledger/pump. Never release admission capacity merely because physicalUP removed the owner. Handler post failure must roll back new state and exact mirrors without inline stock callbacks or restoration of retired authority.
2. Phone APP_SWITCH is tracked with a non-null PairToken but origin=null; pair!=null does not identify a claimed external owner. If phone START is universally queued, an immediate UP removes the PENDING owner and later START fails ownerCurrent, losing ordinary short-tap Recents. Preserve normal phone/unclaimed synchronous post-helper behavior, or prove a distinct ordinary completion protocol that does not lose quick taps. Claimed-only queuing needs an exact origin discriminator, not PairToken existence. Meta/Caps mirrors must be synchronous; old queued work must never republish them over a phone replacement.
3. Stock PWM RECENT_APPS_SWITCHER shows/hides global Recents with no exact owner/display check (snapshot10 generated lines3644–3651). STARTED(A) alone is not authority to hide after B owns the endpoint. STARTA→B (claimed replacement or synchronousphone)→late cleanupA can affect B despite mirror CAS. Track exact delivered endpoint ownership/one-shot cancellation or equivalent actual endpoint guard; test the real PWM branch as well as local mirror isolation. APP_SWITCH has separate thread-local/PWM preload-owner handling, which must not be accidentally bypassed.

Additional controls: post=false and post-throws including uncertain accepted callback; removed-before-commit/committed-before-retire barriers; old cleanup after replacement; cleanup failures aggregating without abandoning later independent owners; repeated duplicate START; Handler freeze with bounded outstanding ledger; exact census epoch captured BEFORE device/key reads, stale epoch preserving saturation/pairs/mirrors and early policy-return paths updating the epoch. Sequential native key-code census plus helper epoch is not asserted to be an instantaneous atomic physical snapshot. No waiting/retry threads are introduced to evade a hung Handler.

Captured external Escape needs its own exact endpoint: normal CAPTURE_KEYBOARD plus the enabled release flag reaches stock QUIT whose Shell implementation ignores original focusedToken/display and removes the current global task. After helper release, a private WMS action must atomically re-resolve the initial input token, same window/task/UID/display/exact live claim and still-current native focus; mismatch/expired/retired/dead/captured-other-target means no-op/cancel. Phone/unclaimed retains stock handling. No public APK SDK authority expansion is implied.
